- [fix] WorkerPollCancel (new action): a cached-pool worker that pushed its `SynchronousQueue.poll` node with its status set cancels it (`awaitFulfill` `isInterrupted()` → `tryCancel`, `SynchronousQueue.java:441-442`), `poll` clears the status and throws (`:938-940`), `getTask` re-polls; base.tla had no such step, so the recorded re-push (`WorkerPollBlock`, intr=false) found the worker already `Idle`. Added `WorkerPollCancel` (Idle ∧ intr → GetTask, intr cleared) to base/MC, and the trace-side `SilentPollCancel`, which fires only when that worker's next event is the re-push and no shutdown has happened (a re-push requires `getTask`'s RUNNING check after the cancel, `TPE.java:1033`). - [fix] ExecutorShutdown / WorkerPollBlock: `shutdown()` calls `interruptIdleWorkers` (`TPE.java:1375, 783-803`), which interrupts every worker in `getTask` ("GetTask"/"Idle"); and a worker that passed `getTask`'s run-state check before the shutdown still pushes its poll node. The model neither interrupted idle workers nor allowed `WorkerPollBlock` after shutdown. `ExecutorShutdown` now sets `intr` of GetTask/Idle workers; `WorkerPollBlock` requires `~exShutdown \/ intr[w]` (Trace: fixed_cached-010).

## Repair Round 1 - Spec / Invariant Changes (RR-001, RR-002)
- [fix-inv] NoDiscardedCompletion (RR-001, MC-3, Case A): Phase 4 reproduced the counterexample (`hunt_s1_timelimit_bfs1.out`) on the real library and found it to be the documented timeout outcome (Guava 22.0 `TimeLimiter.java:79-83, 94, 47-51`; `SimpleTimeLimiter.java:164-166`; `AttemptTimeLimiter.java:22`; 1079/16000 hits, all after the deadline, caller-visible outcome identical to a cancelled timeout). What the code guarantees on the timeout path (a task already NORMAL/EXCEPTIONAL when the timed get decides yields its result, JDK `FutureTask.java:406-410, 436-438, 202-204`) is `GetTimeout`'s guard and cannot fail as an invariant, so the property no longer covers the timeout path; the caller-interrupt part (`ttag = "CallerIE"`, MC-4) is unchanged.
- [fix-inv] CountedImpliesInvokedNoStartRace (RR-002, MC-8, Case A): a never-run counted attempt is now accepted when it timed out (start race or wait in the queue of a thread-limited pool) or was rejected by a running executor without free thread or queue room, the documented bounded-executor behavior (`AttemptTimeLimiters.java:47-50` → Guava `SimpleTimeLimiter.java:56-58`; `AttemptTimeLimiter.java:22, 31`; #29). It still rejects attempts cancelled before they ran by a caller interrupt (D-5, MC-4) and rejections by a shut-down executor (D-10, MC-9), which RR-002's evidence does not cover. Ghost-only support in `SubmitRejected`: `curQueued` is now `~exShutdown` (was TRUE), i.e. TRUE only for a capacity rejection (`TPE.java:1347, 1354, 896-898` vs `:889-893` after shutdown); only this invariant reads `curQueued`.
- [wiring] The revised predicates cannot fail where no caller interrupt (and, for the second, no shutdown) exists, so they were taken out of those cfgs instead of being counted: `NoDiscardedCompletion` off in `MC_hunt_s1_timelimit`, `MC_hunt_s4_executor`, `MC_hunt_s4_shutdown`, `MC_hunt_s4_wrap_samepool`; `CountedImpliesInvokedNoStartRace` off in `MC_hunt_s4_executor`, `MC_hunt_s4_wrap_samepool`. Each line in the cfgs records the reason; `brief-coverage.md` §5 lists where each property is falsifiable, vacuous or off.
